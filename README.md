# AllToZed — память проекта для AI-агента Zed

Бесшовный переход между чатами: чат умер (закрывается вкладка, падает
сервер, сменилась модель, другая машина) — новый агент в той же папке за
1–2 tool-call читает `TASK.md` и продолжает работу с того же места, без
пересказа истории. Память — plain-текстовые файлы + git, без кода,
установки и зависимостей.

Идея и протокол: `IgerOK/allToOne-setup` (агент-независимый вариант);
схема брифинга и контроль качества handoff: `IgerOK/alltoone`. Для Zed —
сведение к минимуму: единственный источник истины `TASK.md` (вместо
`state.json` + `handoff.md` + реестра) и опора на авто-чтение `AGENTS.md`,
которое Zed делает сам.

## Что внутри

| Файл | Роль |
|---|---|
| `AGENTS.md` | Протокол: триггеры записи, статусы, resume, health-check, коммиты. Читается Zed автоматически. |
| `TASK.md` | Пустой шаблон памяти проекта: активная задача (цель, состояние, следующие шаги, решения…) + реестр. |
| `.gitignore` | Исключает `.notes/` (L1-заметки) из git. |

Намеренно не включено: `state.json` и `context/` (второй источник истины —
проблема синхронизации), Python-CLI-пакер и метр контекста (в Zed нет
plugin-системы; пороги handoff — 0.30/0.55/0.65·W — живут в глобальных
правилах пользователя).

## Как это работает

- **Запись (в живом чате).** На milestone-ах агент тихо обновляет
  `TASK.md`: решения, смена TODO, завершение шага. `TASK.md` коммитится
  вместе с кодовым изменением, которое она описывает (один коммит,
  lockstep) — память и код всегда согласованы.
- **Чтение (новый чат).** Пользователь говорит «продолжаем» или «прочитай
  TASK.md и продолжи активную задачу». Агент читает файл, делает
  health-check (цель заполнена, «следующие шаги» конкретны, ≤ 60 строк,
  пути существуют, секретов нет), отвечает 3–5 строк: «Цель: … / Сделано:
  … / Дальше: … — идём?» — и после «идём» продолжает строго с первого
  следующего шага.
- **Качество gate.** Новый чат не переосмысляет «Решения», не
  перечитывает файлы из пакета, не заводит новые подзадачи, пока есть
  активная задача. Если `TASK.md` сломан — агент не выдумывает: предлагает
  восстановить из git или заново инициализировать.

## Применение к проекту (PowerShell, из папки AllToZed)

```powershell
Copy-Item AGENTS.md,TASK.md,.gitignore D:\work\my-project\
cd D:\work\my-project
git add AGENTS.md TASK.md .gitignore
git commit -m "AllToZed init"
```

Если в целевом проекте уже есть свой `AGENTS.md` — слить, не переписать.

Альтернатива: открыть целевой проект в Zed и сказать агенту «Создай
AllToZed для этого проекта» — агент выполнит всё по протоколу `AGENTS.md`,
включая заполнение «Окружения» и «Цели».

## Другая машина

`git clone <проект>` → открыть в Zed → «продолжаем». L2-память
переезжает вместе с репо; L1-заметки (`.notes/`) — только локально.

## Удаление AllToZed

1. Финальный коммит: сказать агенту «сохрани контекст» (обновить
   `TASK.md`).
2. Удалить `AGENTS.md` (или секцию протокола), `TASK.md`; `.gitignore` —
   по желанию. Агенты больше не знают о протоколе.

## Опционально: slash-команда Zed `resume`

Файл `%APPDATA%\zed\resume.md`:

```md
Прочитай TASK.md и продолжи активную задачу по протоколу AGENTS.md:
health-check, брифинг 3–5 строк, жду «идём».
```

Подключение в `settings.json` Zed:

```jsonc
{ "agent": { "custom_commands": { "resume": "%APPDATA%/zed/resume.md" } } }
```

> Ключ `agent.custom_commands` сверь по JSON-схеме настроек Zed — в новых
> версиях имя может отличаться.
